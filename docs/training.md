# Training the NER model

How to produce a new `model.pth`. Everything needed is in this repo except the
training data and the weights, which are too large to commit.

The model is `bert-base-cased` with one classification layer on top. It gives
every word of a command a label from [`data/vocab.slot`](../data/vocab.slot),
such as `B-Action-navigate-to` or `B-Object`. Everything for training lives in `training/`. Training has three steps: generate
labeled example commands with an LLM, convert them to the training format, and
train.

## Files

| File | Role |
|---|---|
| `training/data_generation/generate_data.py` | Generates labeled example commands with Azure OpenAI |
| `training/data_generation/prompt.py` | The prompt: which actions, labels and labeling rules the LLM uses |
| `training/data_generation/to_training_format.py` | Converts the generated JSON to the training format |
| `training/data_generation/output_schema.json` | Reference: the JSON structure the LLM is asked to return |
| `training/train.py` | Trains the model and saves `model.pth` |
| `training/training_loop.py`, `training/dataset.py` | Training loop and data loading, used by `train.py` |
| `data/vocab.slot` | The label list, shared by training and the ROS package |
| `training/example_data/` | A few hand-written examples, for checking the pipeline runs |

`train.py` uses the same model class and label list as the ROS package
(`src/ner_model/ner_model.py`), so trained weights always match what the robot
loads.

The other files in `training/data_generation/` (`data_generation_fct_call.json`,
`data_sample*.json`) are from last year's version with older labels. The current
model doesn't use them.

## Requirements

- Training: `pip install torch transformers pandas tqdm`. A GPU is strongly
  recommended. `bert-base-cased` is downloaded from Hugging Face on first use.
- Data generation: also `pip install openai pydantic python-dotenv`, plus an
  Azure OpenAI deployment.
- ROS is **not** needed for either.

## 1. Generate data

Set the Azure credentials, either in the environment or in a `.env` file in
`training/data_generation/` (never commit it):

```
AZURE_OPENAI_ENDPOINT=...
azure_key=...
AZURE_API_VERSION=...
```

Then run from inside `training/data_generation/`:

```bash
cd training/data_generation
python3 generate_data.py --num-examples 5000 --model gpt-4.1
```

This writes `train_<timestamp>.json`, `dev_<timestamp>.json` and
`test_<timestamp>.json` (an 80/10/10 split). The examples are generated by an
LLM, so each run gives a different dataset.

## 2. Convert to the training format

```bash
python3 to_training_format.py train_<timestamp>.json ../../data/train.txt
python3 to_training_format.py dev_<timestamp>.json   ../../data/valid.txt
```

Each line is one command, as `word:label` pairs followed by the action:

```
go:B-Action-navigate-to to:I-Action-navigate-to the:O kitchen:B-Location <=> navigate-to
```

Every label must be in `data/vocab.slot`, or training stops with a `KeyError`.

## 3. Train

```bash
python3 training/train.py --train data/train.txt --valid data/valid.txt --output model.pth
```

The defaults match how the current model was trained: 4 epochs, learning rate
3e-5, batch size 32, max 45 tokens. Each can be changed with
`--epochs`, `--lr`, `--batch-size` and `--max-length`. Training and validation
loss are printed after each epoch.

To check the pipeline works without real data (the result is useless as a model):

```bash
python3 training/train.py --train training/example_data/train.txt --valid training/example_data/valid.txt --epochs 1 --output /tmp/test.pth
```

## 4. Use the new weights

Copy `model.pth` to `~/data/ner_model/` on the robot, or point the
`ner_model/model_path` ROS parameter at it. See
[teammate_setup.md](teammate_setup.md) for where the weights are looked up. Keep
the training data next to the weights you share, so the model can be retrained
later.

## Adding a new action or entity type

1. Add the `B-` (and, for multi-word spans, `I-`) labels to `data/vocab.slot`.
2. Describe them in the prompt in `training/data_generation/prompt.py`.
3. Regenerate the data and retrain. Old weights stop working as soon as
   `vocab.slot` changes, because the number of labels changes.

[extending_vocabulary.md](extending_vocabulary.md) covers the rest of the
pipeline (mapper, linker, action server).
